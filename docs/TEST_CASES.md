# unified-legal-ai-cn 端到端集成测试用例 (Phase 4)

## 全链路集成测试图谱

```
[输入: 原始事实/材料]
 │
 ▼
 1. DocAnalyzer ───────> (提取法律事实要素，输出要素化 JSON)
 │
 ▼
 2. IssueIdentifier ──> (触发魔鬼代言人 3 轮激辩，生成争议焦点表)
 │
 ▼
 3. Researcher ────────> (触发三阶降级状态机，若涉建工则强注免责后缀)
 │
 ▼
 4. Strategist ────────> (调用三轨对撞机，输出含"抗辩漏洞修复"的预案报告)
 │
 ▼
 5. Writer ────────────> (动态加载 28 专职 Persona 交付模板，生成标准格式法律文书)
 │
 ▼
 6. Reviewer ──────────> (对比 29 项 guards 阻断清单，完成出厂合规审校)
```

## 用例 1：建设工程款拖欠与延误索赔纠纷 (复合交叉领域)

**输入 fact 数据**：

> 分包商（原告）持有总包商（被告）现场项目经理签认的工程量确认单，要求结算 500 万元尾款。总包商以"项目经理无表见代理权、工程延误 45 天、未经竣工验收"为由拒付，并反索赔延误违约金 100 万元。原告主张"未验先用视为质量合格"的裁判规则作为支撑。

**预期断言**：

| # | 断言 | 验证方式 |
|:--|:---|:---|
| A1 | DocAnalyzer 正确将"现场项目经理签认"和"未验先用"抽离为独立事实结构体 | 要素化 JSON 输出中含两个独立 fact 节点 |
| A2 | IssueIdentifier 自动唤醒 devils-advocate，完成原告陈述→被告反驳→法官裁决三轮思考 | 思考链日志可见 plaintiff.md → defendant.md → judge.md 加载 |
| A3 | Researcher 检索时优先读取本地 core-codices 法律 JSON (STAGE-1) | 日志中 STAGE-1 命中，未触发法律数据库 API |
| A4 | Strategist 输出含"抗辩漏洞修复"独立板块 | 策略报告含 `### 抗辩漏洞修复` 章节 |
| A5 | 全程不报路径死锁 | 无 FileNotFound 或相对路径解析错误 |

## 用例 2：新《公司法》股东出资责任与清算纠纷 (成文法更迭领域)

**输入 fact 数据**：

> 某有限责任公司于 2024 年 7 月因经营不善解散，股东甲认缴出资 200 万元，出资交纳红线原本为 2028 年。债权人以公司财产不足清算为由，要求股东甲在未出资范围内对公司债务承担连带清偿责任。股东甲抗辩称"其出资期限尚未届满，享有期限利益"。

**预期断言**：

| # | 断言 | 验证方式 |
|:--|:---|:---|
| B1 | Researcher 检索"股东出资加速到期"时，STAGE-1 直接命中 `../core-codices/laws/company-law-2024.json` | 日志中 STAGE-1 命中，无联网记录 |
| B2 | Writer 在生成清算方案意见书时，动态加载 personas 下的清算模板 | Scheduler 日志可见 persona 加载 |
| B3 | 输出结果贴合 2024 年新规格式（出资加速到期条款） | 引用法条为 2024 版《公司法》条文 |

## 用例 3：巨额合同诈骗与民事欺诈边界对撞 (刑民交叉复杂领域)

**输入 fact 数据**：

> A 公司与 B 公司签订大宗钢材买卖合同，A 公司伪造了银行承兑汇票骗取 B 公司发货，总价值 1200 万元。B 公司起诉要求合同无效并赔偿损失，同时公安机关已对 A 公司负责人以合同诈骗罪立案侦查。A 公司律师辩称本案系民事纠纷，应"先民后刑"。

**预期断言**：

| # | 断言 | 验证方式 |
|:--|:---|:---|
| C1 | Strategist 判定刑民交叉，启动 trirail_collide 三轨对撞（PRC-CBL + PRC-SPC + PRC-CN） | 日志中可见 trirail_collide 调用 |
| C2 | Reviewer 对照 blocking-list.md 中 29 项律师执业红线审查输出 | 审查日志可见 guards 检查记录 |
| C3 | 输出方案不含"协助隐匿犯罪所得"或"恶意阻碍刑事立案"等风险表述 | 全文搜索无违禁表述 |
