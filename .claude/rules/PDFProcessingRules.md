# PDF 处理规则

**版本**: v3.0
**更新日期**: 2026-06-05

## 一、处理优先级

### （一）首选路径

调用 `legal-ocr` 技能对 PDF 或图片执行 OCR。适用范围涵盖本地文件与远程 URL。单文件限 10MB、20 页以内；更大文件需配置令牌切换为标准接口。

成功则取 Markdown 结果。失败则降级。

### （二）备用路径

仅当前者不可用时启用：

- `tesseract` 做图片 OCR
- `pdftotext` 直接提文本

## 二、输出约束

1. 唯一产出为同名 `.md` 文件
2. 仅含结构化信息，不保留原始 OCR 文本
3. 严禁同时产出 JSON、中间图片、布局信息、多版本文档或质量报告

## 三、必提取字段

### （一）案号识别

标准格式：`[年份]省[市/区]民初/行初/刑初[序号]号`。无案号时改用 `{原告}诉{被告}{案由}`。

### （二）当事人

原告、被告、第三人（如有）均需列入。

### （三）案由与法院

从诉讼请求或文书首部提炼案由；并记明审理法院与文书日期。

## 四、零幻觉准则

- 绝不凭空猜测数据
- 难确认字段标"待确认"
- 每条信息标注来源文件
- 多文档交叉印证

## 五、精度要求

| 指标 | 基线 |
|------|------|
| 单文档处理时效 | < 3 分钟 |
| 综合准确率 | > 90% |
| OCR 字符准确率 | > 95% |
| 案号、当事人等关键字段 | 100% |

## 六、案号处置细则

标准案号示例：`[2025]京0105民初1234号`。严禁自编案号；若无案号，只以当事人拼接。输出目录直接置于案件根层，不加 cases 子文件夹。
