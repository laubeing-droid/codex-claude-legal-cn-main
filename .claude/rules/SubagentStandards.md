# 子智能体配置标准

**版本**: v3.0
**更新日期**: 2026-06-05

## 一、双段式结构

每个子智能体配置由 YAML 前置数据与 Markdown 正文组成。

### （一）YAML 头

```yaml
---
name: 唯一标识（小写短横线）
description: 简洁说明调用时机
tools: Read, Write, Bash, Grep, Glob
color: blue
---
```

name 必须唯一。description 面向主智能体的自动路由决策。tools 用逗号分隔，不写 JSON 数组。技能由主智能体动态注入，不在子智能体声明。

### （二）正文

正文即系统指令，是子智能体行为核心指引。

## 二、必备章节

### （一）角色定义

交代法律角色定位、适用场景列表、核心职责逐项说明、可勾选的检查清单、输出硬性约束。

### （二）工作流程

以编号步骤描述操作顺序，每步附简要说明。

### （三）输出标准

引用 OutputStandards.md 等外部规范，自身只补充本 Agent 特有约束，不重复通用格式。

### （四）后续指引

完成后递回主智能体，由主智能体按场景决定继续调度还是结束。子智能体严禁自行调用其他子智能体。末尾附完成标记。

## 三、设计原则

- **单一职责**：每子智能体解决一类问题，不堆叠功能
- **法律术语精准**：使用规范法律用语
- **共享引用**：通过 Rules 文件继承公共约定
- **不硬编码调用链**：工作流编排全归主智能体

## 四、禁止内容

1. 重复的输出格式示例（应引用 OutputStandards.md）
2. 具体实现代码
3. 冗长模板文字
4. 跨智能体调用描述
5. 重复的 联网检索/PDF 处理规则

## 五、校验清单

- YAML 前置数据格式无误，name 小写短横线合规
- description 便于路由决策
- 章节完整（角色/流程/输出/后续指引）
- 无重复定义，全部引用外部规范
- 法律术语专业，完成标识不含后续 Agent 触发语
