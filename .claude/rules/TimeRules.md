# 时间管理规范

**版本**: v3.0
**更新日期**: 2026-06-05

## 一、核心铁律

所有时间戳必须以系统本机时钟为准，严禁杜撰、估算或使用未来时间。

## 二、时间获取

### （一）命令

```bash
date "+%Y-%m-%d %H:%M:%S"   # 完整时间
date "+%Y-%m-%d"             # 日期
```

### （二）适用映射

- 文档创建与修改 — 操作瞬间系统时间
- 立案日期 — 已立的用实际，未立的用当日
- 期限推算 — 从当前日期起算
- 预计节点 — 基于诉讼程序的合理推演

## 三、时间修正流程

发现任何时间戳错误时：

1. 立即中止当前操作
2. 重取系统时间
3. 排查需修正的全部字段
4. 批量改回，覆盖案件信息、时间线、任务截止日、期限起止日、更新历史
5. 检验逻辑连贯性
6. 在变更记录中留下修正日志

## 四、格式统一

| 类型 | 格式 | 说明 |
|------|------|------|
| 日期 | `YYYY-MM-DD` | 标准日期 |
| 时间 | `YYYY-MM-DD HH:MM:SS` | 含时分秒 |
| 剩余天数 | `[X天]` | 倒计时提醒 |
| 预估 | `[预计]` 或 `[预计时间]` | 推断标注 |

## 五、一致性检验

- 所有时间 ≤ 系统当前时间
- 时间线呈过去→现在→未来顺序
- 程序间隔合乎实践（如立案至开庭不小于法定预留天数）
- 同一案件的各文件时间吻合
- 更新历史时间戳反映真实修改时刻

## 六、禁止行为

- 伪造时间戳
- 跳过逻辑校验
- 日期格式混用
- 已完成事项标注未来时间
- 不校验系统时钟直接写入

## 七、时区与 Agent 分工

- 统一采用本地时区
- 每个 Agent 生成时间相关内容前必须先执行 `date` 命令
- 在案件上下文文件中记录时间变更轨迹
