# 案件初始化工具

## 一、功能说明

为诉讼案件或咨询项目创建标准化工作环境，涵盖目录初始化、管理文件生成和材料自动归类。

(一) 支持场景
1. 诉讼案件——12录标准架构，对应完整办案流程
2. 咨询项目——精简2目录结构，聚焦客户材料与工作产出

(二) 类型识别
1. 从用户输入路径关键词（"诉讼""起诉""应诉"等）判断类型
2. 从现有文件内容（起诉状、传票、法律文书）辅助判定
3. 默认按诉讼类型处理，用户可显式指定

## 二、工作流程

(一) 第一步：类型与配置加载
1. 判定案件类型：`诉讼` / `咨询`
2. 加载对应预设配置：`assets/litigation.yaml` 或 `assets/consultation.yaml`
3. 预设定义目录清单、分类规则和管理文件模板

(二) 第二步：创建目录骨架
1. 在目标路径下按预设的 `directories` 列表逐一创建子目录
2. 目录命名格式：`{序号} - {图标} {目录名}`（如 `00 - 日程管理`）
3. 诉讼类型生成全部12个目录；咨询类型仅生成2个

(三) 第三步：生成管理文件
1. 案件信息看板——当事人信息、争议焦点、时间线与任务清单
2. 工时记录——按模板生成空白工时追踪表
3. 期限管理YAML——法定期限节点与倒计时
4. 待办事项——初始任务登记表
5. 咨询项目的管理文件仅包含项目信息卡和待办事项

(四) 第四步：材料自动分类
1. 扫描用户提供的材料文件名，匹配预设分类规则
2. 按文件名关键词映射到目标子目录
3. 文件名无法判定时读取文件内容前几行辅助归类
4. 未命中任何规则的放入默认目录（诉讼：04-证据材料；咨询：01-客户材料）

## 三、编号与命名规范

(一) 案件编号（诉讼）
格式：`{YYMM}{序号} {原告简称} 与 {被告简称} {案由关键词}`

示例：
- `260221 张家宁 与 pokebone模型 著作权`
- `260315 甲公司 与 乙公司 合同纠纷`

(二) 项目编号（咨询）
格式：`{YYMMDD} {客户简称} {对方} {事项关键词}`

示例：
- `260323 张美金 浙江腾宇包装 咨询`
- `260404 顾忆苏 苏州物睿科技 商业秘密`

(三) 材料参照度分级
| 级别 | 说明 | 编号示例 |
|------|------|----------|
| A | 活文档（律师持续迭代的分析/方案） | A-001, A-002 |
| B | 常查材料（关键录音转写、合同原件） | B-009 |
| C | 存档（低信息量、中间版本） | C-019 |
| D | 待激活（压缩包、未处理原始文件） | D-008 |

序号全局连续不重叠，参照度可随项目进展调整。

## 四、与其他技能协作

(一) 上游技能
1. `legal-ocr`——将扫描件PDF转为Markdown后传入分类
2. `legal-text-format`——格式化裁判文书等正式材料

(二) 下游技能
1. `legal-proposal-generator`——基于案件信息生成法律服务方案
2. `litigation-analysis`——对已整理案件材料进行深度分析
