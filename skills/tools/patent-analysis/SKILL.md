# 专利分析工具

## 一、功能概述

对发明和实用新型两类中国专利进行结构化分析，支撑研发决策、风险评估及争议解决场景。

(一) 专利文件认识要点
1. 独立权利要求定义最宽保护范围，是侵权判定的基准
2. 从属权利要求在独立项基础上叠加技术特征，范围逐层缩小
3. 说明书用于诠释权利要求中术语的具体含义
4. 扉页记载专利号、申请日、权利人、IPC分类等基础信息

(二) 文件组成
1. 扉页——专利基信息与法律状态
2. 权利要求书——保护范围的唯一法律依据
3. 说明书——背景技术、发明内容与实施方式
4. 附图——技术方案的视觉参考

## 二、支持场景

(一) 技术要点提取
梳理单项专利的保护范围、技术特征分解与创新点总结。

(二) 多专利比对
比较同族专利或竞争性专利的保护范围差异，评估专利组合覆盖度。

(三) 侵权比对
将产品方案与权利要求逐特征对照，判断落入保护范围的可能性。

(四) 稳定性分析
检索现有技术文献，评估专利被宣告无效的风险与方向。

(五) FTO排查
新产品上市前排查是否触及第三方有效专利的保护范围。

(六) 规避设计
在存在障碍专利时，分析技术绕行方案的可行性。

(七) 价值评价
从法律稳定度、技术先进性及市场空间三个角度评估专利价值。

## 三、侵权分析框架

(一) 判断步骤
1. 分解独立权利要求1的全部技术特征
2. 将被控产品特征逐项与权利要求对比
3. 全部特征对应→侵权成立
4. 存在差异→检查等同原则适用性

(二) 操作规则
1. 从独立权利要求起始，独立项不成立再查从属项
2. 产品匹配独立权利要求即构成基础侵权
3. 同时触及更多从属权利要求，认定更稳固
4. 独立项被无效不影响基于仍维持从属项的主张

(三) 易犯错误
1. 仅读摘要而忽略权利要求的法律意义
2. 混淆独立与从属权利要求进行侵权判断
3. 忽视限定词（如"竖直""滑动"）对范围的影响
4. 用说明书实施例替代权利要求定义的范围
5. 未经特征分解直接给出未论证的结论

## 四、输出规范

(一) 报告通用要素
1. 分析目的与范围
2. 专利基本信息表
3. 权利要求技术特征分解
4. 核心分析结论
5. 风险提示与建议

(二) 场景专项模板
各场景配备独立报告模板，存储于 `references/` 目录。

## 五、技能协作

(一) 上游
1. `legal-ocr`——专利扫描件转Markdown后传入
2. `legal-text-format`——规范专利文本结构

(二) 下游
1. `litigation-analysis`——分析结论用于诉讼支持

## 六、注意事项

1. 分析报告为初步技术参考，非正式法律意见
2. 实务侵权判定还需考虑等同原则、禁止反悔与现有技术抗辩
3. 专利法律状态以官方数据库登记为准
4. 产出的法律文书中需核实权利人名称与官方登记一致
5. 跨境专利分析因各法域规定差异需另行处理
