# 法律问答提取

将散落在聊天记录、邮件往来、咨询纪要中的实务问答整理为可复用的知识资产。

## 一、识别维度

从沟通文本中识别五类有价值内容：

### (一) 直接问答

客户提出具体法律问题，律师给出明确回复的对话段落。

### (二) 追问回应

在初始回答基础上，客户追加细节追问后律师的进一步阐明。

### (三) 风险提醒

律师主动提示的法律风险、合规底线或负面后果预警。

### (四) 操作指引

律师给出的具体步骤、时限、文件清单等可执行动作。

### (五) 普遍关切

不针对特定当事人、具有一般参考价值的基础法律常识阐述。

## 二、处理规则

### (一) 信息脱敏

所有输出必须去除以下可识别信息：
- 客户姓名、企业名称
- 案件编号、合同编号
- 具体金额、日期、地点

用「甲某」「某公司」「约X万元」等占位符替换。

### (二) 质量控制

- 只有形成完整问答闭环的内容才予提取
- 信息残缺导致无法独立的问答对予以舍弃
- 纯行政沟通、寒暄、日程协调等内容跳过

## 三、输出格式

每条问答对包含：

- 问题描述（脱敏后的客户原始关切）
- 律师解答（脱敏后的核心回复）
- 所属维度（对应上述五类之一）
- 价值标签：普遍性、典型性、教育性、复用性

## 四、处理模式

### (一) 单次提取

对用户直接提供的沟通文件即时处理。

### (二) 增量扫描

指定目录后，基于内容哈希判断文件变更，仅对新增或修改内容触发提取。

### (三) 项目聚合

同一子文件夹下的多次沟通记录可合并为单份 QA 输出，便于按客户或案件维度管理。

## 五、归档机制

提取结果按项目/日期归档至 `archive/extractions/`。扫描日志记录文件哈希、处理状态和所属项目。

## 六、使用方式

单文件：
```
/legal-qa-extractor @沟通记录.md
```

批量扫描：
```
/legal-qa-extractor 扫描 ./客户沟通记录/ 目录
```
