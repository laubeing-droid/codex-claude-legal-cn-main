# 中国法律AI系统总入口

## 一、定位

本技能是中国法律 AI 工作系统的统一入口。自动识别律师工作场景，路由到对应领域技能模块。

**主运行平台：WorkBuddy（多Expert并行）**
**兼容平台：CodeX Desktop（串行工作流）**

---

## 二、推理内核检测

启动任务时执行以下检测：

1. 调用 `tools/list` 检查 `trirail_collide` 工具是否可用

### JC 模式（内核可用）

```
模式标注：[JC 认证]
法律护栏：由 juris-calculus 自动执行（不加载 guards 文件）
          → prc_us_alignment.py 三层看门狗（CBL阻断/SPC倾向/程序正义）
知识技能：不加载（委托 JC 推理）
工具技能：正常加载
阻断概念：跳过自检，由 JC 内核执行
```

### Prompt 模式（内核不可达）

```
模式标注：[JC 不可达，Prompt 推理]
法律护栏：加载 blocking-list.md（29项阻断速查）
          + meta-rules.md（五层判定方法论）
知识技能：降级到内联推理模板
工具技能：正常加载
阻断概念：输出前逐条扫描 29 项标记
```

## 三、领域路由

### （一）路由规则

根据输入关键词自动匹配目标领域（按业务频次排序）：

| 优先级 | 关键词 | 目标领域 | 分类 |
|:------:|:-------|:---------|:----:|
| 1 | 诉讼、仲裁、执行、保全、证据、代理词、答辩 | litigation-legal | 🟢 核心 |
| 2 | 合同审查、违约、补充协议、函件、NDA | commercial-legal | 🟢 核心 |
| 3 | 公司、股权、投资、尽调、并购、股东争议 | corporate-legal | 🟢 核心 |
| 4 | 劳动、社保、解除、竞业、规章制度、工资 | employment-legal | 🟢 核心 |
| 5 | 隐私、个保法、数据出境、PIA、数据合规 | privacy-legal | 🟢 核心 |
| 6 | AI治理、算法、模型备案、伦理审查、GenAI合规 | ai-governance-legal | 🟢 核心 |
| 7 | 产品上线、营销合规、广告法、功能风险 | product-legal | 🟢 核心 |
| 8 | 商标、专利、著作权、开源合规 | ip-legal | 🟡 可选 |
| 9 | 监管、政策变化、法规监控、意见征询 | regulatory-legal | 🟡 可选 |

### （二）路由优先级

1. **精确匹配**：关键词直接命中单一领域，立即激活
2. **多域匹配**：激活最相关的前两个领域，由用户确认
3. **零匹配**：加载通用上下文，询问用户需求
4. **冷启动强制**：如缺少 `.claude/practice-profile.json`，提示运行 `/cold-start`

## 四、推理链锁定

### （一）强制规则

- 民商事领域：强制使用**请求权基础分析法**
- 行政法领域：强制使用**行政行为合法性审查框架**
- 禁止使用 IRAC（Issue-Rule-Application-Conclusion）等境外推理结构
- JC 在线时：推理链由内核自动校验
- JC 离线时：手动执行推理链检查

### （二）阻断概念过滤

- **JC 在线**：跳过——由 `prc_us_alignment.py` 三层看门狗执行
- **JC 离线**：加载 `blocking-list.md`（29项）+ `meta-rules.md`（五层判定）

---

## 五、自检机制

JC 在线时跳过。JC 离线时输出末尾静默执行：

1. 推理框架是否合规（请求权基础/合法性审查）
2. 阻断概念是否已替换（匹配 29 项清单）
3. 法条引用是否含具体条目号

---

## 六、输出限制

- 所有输出均为律师审查草稿，不构成法律意见
- 法规引用需标注版本和施行日期
- 提交或发送前需经执业律师审核
- 所有输出标注当前推理模式 `[JC 认证]` 或 `[JC 不可达]`
