# 法条检索

## 一、检索总流程

法律检索遵循五阶段递进结构：准备（界定目的与收集事实）→ 思维（选择方法论框架）→ 执行（运行检索式）→ 复核（交叉验证与涵摄检验）→ 成果（产出检索报告）。

## 二、准备阶段：事实确认

进入检索前必须逐一核实以下要素，缺一不可：

（一）纠纷类型归属——劳动、合同、侵权、婚姻、行政或其他具体领域。

（二）双方主体地位——当事人的法律身份及相对关系。

（三）核心事实链条——时间节点、行为过程、已产生的后果。

（四）争议焦点提炼——当事人主张的权利或救济目标。

（五）管辖地域信息——是否涉及地方性规范的适用。

（六）法律关系的初步定性——合同关系、侵权关系、劳动关系等。

以上信息须经检索需求方确认无误后，方可启动法律依据的查找。严禁在事实未核实的情况下调用任何法律数据接口。

## 三、思维阶段：三大方法框架

### （一）法源位阶路线

以法的效力层级为线索逐级扫描。中国法的正式渊源按位阶降序排列：宪法 → 法律 → 行政法规 → 地方性法规 → 部门规章 → 司法解释。检索时自高位阶向低位阶递进，记录无效路径以标注立法空白区域。

同一位阶内部的适用规则依《立法法》第九十二条处理：特别规定相对于一般规定优先适用，新规定相对于旧规定优先适用。不同位阶的规范冲突则按《立法法》第八十七条至第九十五条规定的裁决程序解决。

### （二）法律关系路线

以案件事实的演进时序为轴，将法律关系拆解为成立、生效、履行、变动、终止各节点逐一检视。从主体资格（是否具备权利能力与行为能力）出发，顺次确定权利类型（支配权、请求权、抗辩权、形成权），再按"特别规定→分则条款→总则条款"的顺序匹配准据法。最后分解该规范的构成要件，将案件事实逐项比对其入。

### （三）请求权路线

以诉讼请求为起点，从低阶请求权向高阶请求权逐层排查，确定最有利于当事人的诉讼策略。检索次序为：合同请求权 → 类契约请求权 → 身份法请求权 → 无因管理请求权 → 物权请求权 → 占有保护请求权 → 不当得利请求权 → 侵权请求权。对每个请求权按三阶结构检视：是否成立（构成要件该当性、违法性、有责性）→ 是否未消灭（清偿、抵销、时效）→ 是否可行使（是否存在抗辩事由）。

## 四、效力甄别五项审查

对检索命中的每一条文，须经过五步递进审查：

（一）真实性审查——至少用两个独立权威数据库交叉比对，确认条文内容无误。

（二）有效性审查——核查是否已被明示废止或因新法施行而默示失效，判别"法释"文号与一般业务答复的区别。

（三）适用性审查——判断该规范的对人管辖范围（属人、属地、保护、折中四原则）与空间适用范围（全国性还是地方性）是否覆盖本案。

（四）时间效力审查——比对案件行为发生时间与条文生效时间，确定新旧法适用关系。实体规范原则上不溯及既往（《立法法》第九十三条），程序规范即时适用。

（五）位阶审查——确认条文的制定机关与效力层级，排除无权机关发布的内部文件或其他不具有裁判依据地位的材料。

## 五、执行阶段：三种检索技法

（一）体系检索法。自法律体系的宏观结构向下梳理，先在基本法的原则性条文中确定框架，再到特别法、配套行政法规和司法解释中查找细化规则。利用专业数据库中的条文关联索引功能，追踪援引该条的下位规范和裁判文书。

（二）关键词检索法。将案件争议提炼为两组词汇——规范用语（法律概念中的标准术语）与实务用语（行业习惯表述）——交叉组配后构建布尔检索式。先用宽泛组合探测范围，再逐步追加限定条件收缩结果集，实现从模糊到精确的迭代收敛。

（三）案例倒查法。在陌生领域或法条定位困难时使用。以案件事实描述词为检索入口，在裁判数据库中寻找类案。直接定位判决书的说理段落和条文援引部分，反向推导出可适用的实体法条文和司法实践中的解释倾向。

## 六、复核阶段：质控与涵摄

（一）查全率保障。切换不同数据库用相同检索式执行，比对结果集的重叠率。重叠率低于一半时须扩大检索。同时用体系检索与关键词检索双路线交叉验证，核查是否遗漏了地方性法规或最新修订。

（二）查准率优化。将检索结果逐条回代入本案进行涵摄检验。从六个维度比对：事实相似度、法律关系匹配度、效力位阶适配性、裁判观点的时效性、地域管辖的匹配性、结果数量的适度性。差异明显者直接排除。

（三）二次检索决策。当查全与查准无法同时达标时，依据矩阵判断是扩大还是缩限检索口径。所有调整必须围绕"该规范能否适用于本案"这一核心问题展开，避免为追求指标而引入无关规范。

## 七、成果阶段：检索报告

报告按以下顺序组织：检索目的陈述 → 所用数据库及关键词记录 → 有效法规按位阶降序列表（逐条标注文件全称、文号、生效时间、效力状态、条文原文）→ 规范冲突分析 → 检索结论（标注结论强度：高概率成立 / 存在争议 / 证据不足）。禁止使用绝对化表述。结论部分须同时揭示有利规范和反面论据，保持中立立场。

## 八、运行降级协议

系统执行检索时，严格按以下优先级逐级降级：

（一）本地权威库阶段。启动时读取 `plugin-registry.json`，定位类型为 `laws` 的外部数据插件路径。若本地缓存的权威裁判规则数据库中精准命中，该结果作为确定性依据直接返回，终止后续检索链路。

（二）外部在线检索阶段。本地未命中时，按优先级逐一调用外部数据接口：商业法律信息检索服务 → 裁判文书官方开放平台 → 本地离线索引备选。

（三）配置异常降级。若 `plugin-registry.json` 不可读或格式损坏，立即跳过全部本地阶段，直接转入外部在线检索通道。严禁在此情况下使用任何预置的静态文件路径进行文件系统探测。

## 九、真实性约束

输出的每一条法条必须源于实际检索的返回结果，禁止凭记忆编造条文编号、文件名称或生效日期。若运行环境中未接入任何法规检索工具，凡涉及具体条文之处统一标注"[待查]"。
